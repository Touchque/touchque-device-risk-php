# Changelog

format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [1.1.0] — 2026-11-26

### Added
- **`botCheck([...])`: check one visitor request on your server for bots** (`POST /device-risk/bot-check`), also the ones that never run the page's JavaScript (ChatGPT-User, GPTBot, Meta's crawlers, curl, scripts). Send `ip` and `headers` (`[[name, value], ...]` in the order received, `[]` for a request that had none; a `[name => value]` map goes as an object, its order unknown), and optionally `method`, `url` (only the host and path are sent, never the query string or a user:password@), and, only when your edge tells you what the visitor's were, `httpVersion` (`1.0`, `1.1`, `2`, `3`; `HTTP/1.1` and `h2` are read too, anything else is left out) and `tls` (`ciphers`, `ja4`). Authorization, Cookie, Proxy-Authorization, X-Api-Key and Set-Cookie always go with empty values, their names kept for the order; HTTP/2 pseudo-headers (`:path` holds the query string) and null values are left out. A missing or wrong `ip`, malformed headers or an unknown field throws `TouchqueConfigException` before anything is sent; what a visitor sends never does: past 100 headers the rest is left out, a name is cut to 128 characters and a value to 4096 (counted as the API counts them), the longest values are cut further when the request would pass the API's 32 KB, and `truncated: true` tells Touchque; a header HTTP does not allow, a method other than 1 to 16 letters or a URL Touchque could not read is left out. An `::ffff:` IPv4 address goes as the IPv4 one.
- `TouchqueDeviceRisk::botCheckRequestFromServer(?array $server = null, ?string $ip = null)`: the request from `$_SERVER` or Laravel's `$request->server->all()`: the HTTP_* headers in PHP's order (with CONTENT_TYPE / CONTENT_LENGTH), REMOTE_ADDR unless you pass the address your framework trusts, the method and the host and path (the path alone without a host). It never reads X-Forwarded-For and never sends SERVER_PROTOCOL (behind a proxy, the proxy's connection).
- The answer, read by `TouchqueDeviceRisk::parseBotCheck()`: `bot` (`result`, `category`, `provider`, `name`, `identity` verified / unverified (a spoofed name) / claimed, `verifiedBy`, `confidence`, `rule`, `reasons` with `code` and `text`), `network` (`asn`, `asnOrg`, `countryCode`, `hosting`) or null, `suggestion` (allow, block or challenge: advice in shadow, never enforced by Touchque) and `rulesVersion`. Fields and values this version does not know come through as they were sent; what it cannot read is "cannot tell" (`not_detected`, `allow`), never a block. Constants `BOT_CHECK_RESULTS`, `BOT_CHECK_CATEGORIES`, `BOT_CHECK_IDENTITIES`, `BOT_CHECK_VERIFIED_BY`, `BOT_CHECK_CONFIDENCES`, `BOT_CHECK_SUGGESTIONS`, `BOT_CHECK_HTTP_VERSIONS` and `BOT_CHECK_BLANKED_HEADERS`.
- `visitor['mark']`: the mark actually applied to the identification (`step_up` always, `trusted` only when the browser matched by its stored key or id, never by traits, else null), in `check()` and `getEvent()`; `check()` / `TouchqueDeviceRisk::parse()` read any other value as null. `visitor['status']` stays your admin's mark. Absent from older servers.
- **The kind of network** in `network` (`check()`, `getEvent()` and each `searchEvents()` row), passed through as the API answers it: `kind` (`residential`, `mobile_carrier`, `education`, `business`, `public_wifi`, `hosting`, `proxy`, `vpn`, `tor`, `relay` or `unknown`; `TouchqueDeviceRisk::NETWORK_KINDS`, an open list: new values may be added in minor versions), `kindSource` (`address`, `network`, `mixed`, `network_open` or `name`), `vpn`, `shared` with its "at least" counts `sharedVisitors24h` and `sharedAccounts24h` (1, 2, 5, 10, 100 or 1000), and `lookAlikeMatching`. Absent from older servers; null for identifications from before them. `proxy` and the `type` `relay` are now documented too.
- `searchEvents()` takes `networkKind` (one kind of network; identifications from before network kinds never match) and `shared` (`true` or `false`, sent as `true` / `false`; `false` finds the ones counted and not shared, so one that was not counted matches neither). Older servers ignore both.
- **AI agents in `bot`** (`check()`, `getEvent()` and each `searchEvents()` row), on servers since 2026-11-25: `tools` can name `claude_agent` (the Claude app's browser or Claude in Chrome), `comet_agent` (Perplexity Comet), `genspark_agent`, `browser_use`, `stagehand` and `skyvern` next to `selenium`, `playwright`, `puppeteer`, `phantomjs`, `nightmare` and `headless_chrome`, each also as the reason `tool_<name>`; the reasons `cdp_input`, `input_no_focus`, `insert_text_bulk` and `scripted_click` are new, and `headless_window` and `emulator` (sent since 2026-11-24) are now documented. Documented in `parse()`; the values come as the API sends them, absent from older servers.

## [1.0.0] — 2026-11-24

### Added
- **Touchque Device Risk as its own package.** Device risk leaves the main PHP SDK (`touchque-authenticator/php-sdk` 6.0.0 no longer has `$tq->deviceRisk`): `new TouchqueDeviceRisk(?Config $config = null)` with its own small client (the same API key and secret, `TQ_API_KEY` / `TQ_API_SECRET` / `TQ_API_URL`, the same request signing, timeout and exceptions as the main SDK, in `Touchque\DeviceRisk\Exceptions`).
- `check($requestId, $event, $externalUsername, $clientIp, $deviceRisk)` (`POST /device-risk/check`), `getEvent($requestId)` (`GET /device-risk/events/{requestId}`), `searchEvents([...])` (`GET /device-risk/events`) and `TouchqueDeviceRisk::parse()`, as they were on `$tq->deviceRisk`.
- **`activity([...])`: report what a visitor did that your server saw** (`POST /device-risk/activity`): `type` (`payment_attempt`, `login_failed`, `not_found`, `forbidden`, `otp_sent`, `code_failed`), `requestId`, `visitorId`, `clientIp`, `externalUsername`, `outcome` (`approved`, `declined`, `error`), `card` (`['bin' => 6-8 digits, 'last4' => 4 digits]`), `phone`, `path`. Answers `recorded`, `visitorId`, `signals` (`abuse_card_testing`, `abuse_card_shared`, `abuse_login_failures`, `abuse_probing`, `abuse_otp_pumping`, `abuse_code_guessing`) and `pathClass`. A card that is not exactly a BIN and the last 4 digits (a card number, a `number` or `pan` key) throws `TouchqueConfigException` before anything is sent.
- `check()` answers carry `suspect` (the suspect score in shadow: `score` 0-100, `band`, `wouldDo`, `mode`, `reasons` with `code`, `points`, `by`, `text`) and `accountDevice` (`status` known, likely, new or first, `visitorId`, `since`); `TouchqueDeviceRisk::parseSuspect()` and `parseAccountDevice()` read them from `getEvent()` answers and `searchEvents()` rows. `MATCHED_BY` lists `fpc` (the first-party cookie).
- `WebhookEvents::DEVICE_RISK_SIGNAL` and `WebhookEvents::DEVICE_RISK_ALERT` (were `Webhook::EVENT_DEVICE_RISK_*` in the main SDK).
- The `bot` array of `check()`, `getEvent()` and each `searchEvents()` item carries `type` (`ai_agent`, `automation`, `script` or null), `tools`, `agent` and `input` on servers since 2026-11-24; the API can return the signal codes `device_input_synthetic` and `device_ai_agent` (a number-matched step-up only, never a block).
